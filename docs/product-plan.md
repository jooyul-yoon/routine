# 루틴 앱 제품 계획 — 첫 버전 운영 규칙

상태: 경쟁·알림·공개·예외 처리 규칙 확정. 화면 구성과 구현 방식은 다음 설계 단계에서 정한다. 아래의 확정 규칙은 아직 앱에 구현된 기능을 뜻하지 않는다.
확정일: 2026-11-16. 사용자가 직전 추천안에 동의한 내용을 반영했다. 현재 앱은 요구를 탐색하기 위한 초안이다.

## 제품의 목적

휴대폰에서 적은 조작으로 실천을 기록하고, 적절한 알림과 진행 상황 확인으로 습관 형성을 돕는다. 친구와는 각자 정한 전체 루틴의 달성률을 비교한다.

## 사용자가 밝힌 요구

- 목표는 여러 형태로 커스터마이즈할 수 있어야 한다.
- 모든 루틴은 완료·미완료 체크박스로 기록한다. 횟수·양·시간 입력과 타이머는 도입하지 않는다. 물도 하루 목표를 달성했을 때 한 번 체크한다.
- 루틴마다 하루 최대 한 번만 완료로 집계한다. 같은 루틴을 같은 날 두 번 실천해도 추가 점수는 없다. 주간 목표는 실천한 날 수인 주 N일로 집계한다.
- 앱의 중심 목적은 습관 형성을 최대한 돕는 것이다.
- 친구와는 각자 정한 전체 루틴의 달성률을 비교하고 싶다. 공통 목표를 정하는 방식 대신 개인 전체 계획을 기준으로 하는 방향을 선택했다.
- 전체 달성률은 실천 횟수를 합산한다. 루틴별 달성률을 평균하는 방식은 채택하지 않는다.
- 엑셀은 노트북을 열어야 하는 점이 불편하다.
- 휴대폰의 Google Sheets에서는 작은 체크박스를 누르기 어렵다.
- 알림은 아침·저녁 두 차례다. 아침에는 루틴과 오늘 할 일을 리마인드하고, 저녁에는 오늘의 루틴을 정리하도록 안내한다. 기본 시각은 오전 8시·오후 9시이며 사용자가 각각 조정하거나 끌 수 있다. 모두 완료한 날에도 긍정적인 저녁 정리 알림을 보낸다. 휴대폰에서 쉽게 쓰는 것이 가장 중요하다.
- 루틴 이름과 상세 실천 기록은 사용자가 선택해서 친구에게 공개한다. 전체 달성률 계산과 상세 정보 공개 범위는 구분한다.
- 홈 화면 위젯을 원한다.
- 제공한 WHOOP 화면에서는 루틴별 주간 목표 횟수와 요일별 실천 상태를 한 카드에서 볼 수 있다. 화면 예시는 사용 방식 참고이며 그대로 복제하기로 결정한 것은 아니다.

## 제안: 목표 설정과 기록 동작을 구분

목표를 다양하게 설정해도 일상적인 기록은 간단하게 유지한다.

| 목표 주기 제안 | 예시 | 기본 기록 동작 |
| --- | --- | --- |
| 매일 | 물 2L 마시기, 비타민 | 목표를 채웠을 때 완료 체크 |
| 지정 요일 | 월·수·금에 운동 | 해당 날짜에 완료 체크 |
| 주 N일, 요일 자유 | 이번 주 운동 3일 | 실천한 날 체크, 주간 2/3 표시 |

`물 2L`, `기도 15분` 같은 성공 기준은 이름이나 설명에 담고, 실천했을 때 체크한다. 숫자 입력이나 타이머를 요구하지 않는다. 체크는 다시 눌러 취소할 수 있도록 한다.

**결정: 루틴별 하루 한 체크, 주 N일 집계.** 각 루틴과 날짜의 조합에는 완료·미완료 상태 하나만 둔다. 같은 날 같은 루틴을 여러 번 실천하거나 중복 체크해도 완료 수가 늘어나지 않는다. 체크 취소와 다시 체크는 동일한 상태를 변경하는 동작이다. 매일·지정 요일·주 N일 목표 모두 이 기록 방식을 사용한다.

목표 변경의 적용 시점을 저장해 지난 목표를 소급 변경하지 않는다. 경쟁 참여 중인 주의 목표 변경은 다음 주부터 반영하며, 즉시 변경 예외는 아래 운영 규칙을 따른다.

## 제안: 휴대폰 사용 흐름

1. 앱의 첫 화면에서 오늘 실천할 루틴과 요일 자유 목표의 남은 진행량을 본다.
2. 체크박스만 작게 누르는 대신 루틴 행 전체를 큰 터치 영역으로 사용한다. 잘못 누른 완료는 쉽게 취소한다.
3. 아침에는 오늘의 루틴과 할 일을 리마인드하고, 저녁에는 오늘의 루틴 정리를 안내한다. 아침·저녁의 시각과 켜짐 여부는 사용자가 각각 바꿀 수 있다.
4. 위젯에는 사용자가 고른 루틴을 표시한다. 앱을 열지 않고 완료 처리하는 경험이 목표다.
5. 주간 화면에는 WHOOP 참고 화면처럼 루틴별 요일 표시와 주간 목표 달성량을 함께 보여준다.

아침에는 오늘의 루틴과 할 일을 확인하도록, 저녁에는 오늘의 루틴을 정리하도록 안내한다. 저녁 알림은 미완료 항목을 재촉하는 것으로 한정하지 않는다. 모두 완료한 날에도 긍정적인 문구로 기록 확인과 하루 마무리를 안내한다. 요일별 끄기와 알림에서 바로 체크·나중에 하기는 별도 검토 후보이며 아직 확정 기능은 아니다.

확정 기본값은 기기 현지 시각 오전 8시·오후 9시다. 둘의 시각과 켜짐 여부를 각각 바꿀 수 있다. 완료한 날의 저녁 문구 예시는 “오늘 루틴을 모두 마쳤어요. 기록을 확인하고 하루를 마무리해보세요”다. 기본 리마인더는 하루 두 번을 넘기지 않는다. 실제 문구 표현은 화면 설계에서 다듬는다.

오늘 할 일은 아침 리마인더에 포함하는 기능으로 유지한다. 루틴과 일회성 할 일을 첫 화면에서 어떻게 배치할지는 미정이다. 기분·수면·메모는 현재 초안에 존재하며, 습관 체크를 방해하지 않는 보조 기능으로 둘지 별도 화면에서 다룰지 미정이다.

## 친구 경쟁: 개인 전체 루틴 달성률 비교로 결정

사용자는 친구끼리 각자 정한 전체 루틴의 달성률을 비교하는 방향을 선택했다. 친구끼리 같은 습관이나 같은 목표에 합의하는 방식은 기본 경쟁 모델로 채택하지 않는다.

각자의 목표 난이도와 개수는 다를 수 있다. 점수는 자신의 계획을 지킨 정도를 나타내며, 서로 같은 양이나 난이도의 실천을 했다는 의미는 아니다.

### 결정: 실천 횟수 합산

예시: 한 주가 끝났을 때 물 마시기 목표 7일을 모두 지키고, 운동 목표 3일은 한 번도 지키지 못했다.

사용자는 전체 완료 횟수를 전체 계획 횟수로 나누는 방식을 선택했다.

전체 달성률 = 전체 완료 체크 수 / 전체 계획 체크 수 × 100.

완료 체크 수는 서로 다른 루틴·날짜 조합의 완료 상태를 센다. 같은 루틴의 같은 날짜 기록을 중복 합산하지 않는다.

예시 결과는 7 / (7 + 3) = 70%다. 계획한 체크 한 번마다 동일 비중이고, 매일 하는 루틴의 비중이 주 3일 하는 루틴보다 더 크다. 루틴별 달성률의 평균은 사용하지 않는다. 산식은 목표 난이도를 자동 보정하지 않는다. 목표를 초과한 실천은 실제 기록에는 남기되, 경쟁 점수에는 루틴별 목표까지만 합산한다.

### 확정 운영 규칙

사용자가 2026-11-16에 추천안에 동의해 아래 규칙을 첫 버전의 기준으로 확정했다.

#### 비교 기간

- 주간 비교를 기본으로 한다. 각 사용자의 기록 기준 시간대에서 월요일 0시부터 일요일 밤까지 7일의 실천을 같은 주차끼리 비교한다.
- 주중에는 전체 주간 계획에 대한 진행률과 임시 순위를 표시한다. 주간 목표 10개 중 수요일에 3개를 했다면 3/10, 30% 진행 중이다. 남은 70%를 그 시점의 실패로 표시하지 않는다.
- 오늘의 달성률은 별도로 볼 수 있다. 월간은 장기 기록을 돌아보는 용도로 둔다. 일간·월간 경쟁도 제공할지는 미정이다.
- 다음 월요일 정오까지 지난주 체크를 보완할 수 있게 하고, 참여자 전원의 보완 기한이 지나면 최종 순위를 확정한다. 자세한 예외는 아래에 정리한다.

#### 초과 달성

- 실제 실천량은 6/5처럼 목표를 넘긴 만큼 표시한다.
- 경쟁 점수에는 루틴별로 목표까지의 완료 체크만 합산한다. 루틴별 평균으로 계산하는 것이 아니다.
- 확정 산식: 점수에 반영할 완료 수 = 각 루틴의 `min(실천한 날 수, 목표 일수)`를 합한 값. 이를 전체 계획 체크 수로 나눈다.
- 예: 물 7일·운동 3일이 목표이고, 실제로 물 5일·운동 5일을 했다면 원래 실천 기록은 10일이다. 목표까지만 점수에 반영하면 (5 + 3) / (7 + 3) = 80%다. 운동 초과 2일로 물 미달성 2일을 상쇄하지 않는다.

#### 휴식

- 처음부터 정한 휴식일은 계획에 포함하지 않는다. 월·수·금 운동 목표는 3개 체크가 분모이며 나머지 4일은 미달성이 아니다. 요일 자유 주 3일 목표도 분모는 3이다.
- 주간 경쟁이 시작된 뒤 갑자기 쉬는 날이 생겨도 해당 주 경쟁의 분모는 자동으로 줄이지 않는다. 예: 매일 목표 7일에서 하루 쉬고 6일 실천하면 6/7이다.
- 개인 기록에 쉼을 표시하거나 이후 계획을 조정할 수는 있다. 갑작스러운 쉼은 해당 주 경쟁 점수의 분모를 줄이지 않고, 필요하면 이번 주 경쟁 참여를 종료한 뒤 개인 계획을 즉시 조정할 수 있다.

#### 진행 중 목표 변경

- 목표를 주 5일에서 2일로 낮췄을 때 이미 2일 실천했다면 점수가 2/5=40%에서 2/2=100%로 바뀔 수 있다. 진행 중 점수의 분모를 바꾸면 생기는 문제다.
- 경쟁 참여 중인 주의 루틴 추가·보관·목표 일수·요일 변경은 다음 주 계획부터 반영한다. 이번 주 목표는 그대로 보여주고 다음 주 계획을 편집하는 방식으로 혼동을 줄인다. 경쟁에 참여하지 않는 연습·개인 기록 상태에서는 즉시 편집할 수 있다.
- 이름·아이콘·공개 범위·알림 시각처럼 점수에 영향을 주지 않는 설정은 바로 변경할 수 있다.
- 당장 목표를 바꿔야 하면 이번 주 경쟁을 종료한 뒤 개인 기록은 계속할 수 있다. 그 주는 순위에서 제외하고 다음 주부터 다시 참여한다. 기존 참여 상태를 삭제하거나 같은 주에 재참여해 점수를 다시 고르는 흐름은 허용하지 않는다. 개인 화면만 바꾸면서 경쟁에는 보이지 않는 옛 목표를 남기는 방식은 기본안으로 삼지 않는다.

동점 공동 순위와 함께 성공하는 방식도 후보로 남긴다.

### 결정: 상세 정보는 선택 공개

점수 계산에는 전체 루틴을 포함한다. 루틴 이름과 상세 실천 기록은 사용자가 루틴별 공개 단계를 선택해 공개한다. 비공개 루틴도 전체 달성률 계산에 포함하며, 공유 화면에는 허용한 정보만 표시한다. 수면·기분·개인 메모는 루틴 공유에 포함하지 않는다.

첫 버전에는 루틴별로 아래 세 단계 중 하나를 선택한다. 새 루틴의 기본값은 비공개다.

1. 비공개: 이름과 루틴별 실천 기록을 보여주지 않는다. 전체 달성률에는 포함한다.
2. 이름만 공개: 루틴 이름만 보여준다.
3. 이름과 이번 주 기록 공개: 이름과 현재 주차의 요일별 체크를 보여준다. 전체 과거 기록을 자동 공개하지 않는다.

수락한 친구에게 적용하며, 친구마다 세부 권한을 따로 설정하는 기능은 첫 버전 기본안에서 제외한다. 공개 범위를 낮추면 이후 조회에서 즉시 반영하도록 한다.

### 확정 예외 처리

- **중간 주 참여:** 즉시 개인 기록과 친구 진행률 조회를 시작한다. 첫 주는 연습으로 표시하고 다음 주부터 정식 순위에 참여한다.
- **기록 보완:** 각자의 기록 기준 시간대에서 월요일 정오까지 지난주 실제 실천 중 빠뜨린 체크를 보완할 수 있다. 월요일에 새로 실천한 행동을 지난주 실적으로 넣는 기간은 아니다.
- **확정 후 수정:** 이후에도 개인의 과거 기록은 수정할 수 있지만 이미 확정한 순위와 점수는 바꾸지 않는다. 랭킹에 ‘확정 점수’를 표시한다. 오프라인 대기 기록도 공식 마감 전에 서버로 동기화되어야 해당 경쟁에 반영하고, 이후 도착한 기록은 개인 기록으로 보존한다.
- **기록 기준 시간대:** 처음에는 휴대폰 시간대를 기본값으로 선택하고 이후 고정한다. 날짜·요일·주간 목표는 이 시간대로 집계한다. 여행 중 기기 시간대가 바뀌어도 과거 기록과 진행 중 주차를 자동으로 바꾸지 않는다. 기록 기준 시간대 변경은 다음 주부터 반영하고 기존 주차의 기준은 보존한다.
- **알림 시간대:** 오전 8시·오후 9시 같은 생활 알림은 기기의 현재 현지 시각을 따른다. 기록 기준 시간대와 다를 때 기록 화면의 날짜·기준 시간대를 명확하게 보여준다.
- **다른 시간대의 친구:** 각자의 고정 기준에서 같은 월~일 7일을 비교한다. 해당 주 참여자들의 시간대를 주초에 저장하고, 가장 늦게 끝나는 월요일 정오가 지난 뒤 그룹 순위를 확정한다. 다른 사람의 기한을 기다리는 동안 마감 대기 상태를 표시한다. 중간 주 연습 참여자는 이번 주 공식 마감을 늦추지 않는다.
- **즉시 목표 변경:** 이번 주 경쟁 참여 종료 → 개인 계획 즉시 변경 → 다음 주 재참여를 허용한다. 기록은 지우지 않는다.

친구 기능을 추가할 때 기존 개인 `routine_journals` 전체 문서를 친구에게 읽게 하는 접근 정책을 추가하지 않는다. 챌린지·초대·참여·공유 진행 기록을 별도로 설계하고 합의한 집계 규칙을 서버에서도 검증해야 한다.

## 디자인 기준

사용자가 지정한 [OpenAI UI guidelines](https://developers.openai.com/plugins/concepts/ui-guidelines)를 시각적·상호작용 참고 기준으로 삼는다.

- 시스템 글꼴과 일정한 글자 위계를 사용하고 불필요한 크기 변화를 줄인다.
- 텍스트·배경은 차분한 기본색을 사용하고 주요 동작과 완료 상태에 강조색을 제한한다.
- 여백·정렬·아이콘을 일관되게 유지하고 장식보다 상태와 체크 동작이 먼저 보이도록 한다.
- 명암 대비와 글자 확대를 지원하며, 확대해도 내용과 조작이 잘리지 않도록 한다.
- 간단한 동작은 화면 이동을 줄인다. 루틴 행 전체를 터치하기 쉽게 하고 완료 변경을 즉시 보여준다. 큰 터치 영역과 즉시 피드백은 사용자의 모바일 요구에 따른 앱 설계 제안이다.

원문은 ChatGPT 플러그인 UI 가이드다. 독립적인 iOS·Android 앱에는 시각 원칙을 적용하되, ChatGPT 인라인 카드의 동작 개수 제한·탭 금지나 대화 입력창 전제까지 앱 전체에 적용하지 않는다. 웹용 `@openai/apps-sdk-ui`를 네이티브 앱에 그대로 도입하는 결정도 아니다.

## 구현 순서 제안

1. 목표 주기, 기록 동작, 날짜별 상태, 경쟁 방식의 제품 규칙을 정한다.
2. 위젯의 직접 체크와 앱 종료 상태의 기록 보존을 작은 실제 기기 실험으로 먼저 검증한다.
3. 커스텀 목표·큰 터치 영역·알림·위젯을 연결해 개인 습관 기록 경험을 완성한다.
4. 합의한 규칙에 따라 친구 초대와 챌린지를 추가한다.

계획 단계에서는 기존 앱 코드나 운영 DB를 변경하지 않는다.

## 위젯과 알림의 기술 검토

아래는 2026-11-15에 확인한 기술 검토 메모다. 실제 구현 경로를 결정할 때 공식 문서와 프로젝트 버전을 다시 확인한다.

- 현재 앱은 Expo SDK 57이다. 이 버전의 공식 `expo-widgets`는 iOS 전용이고 Expo Go에 포함되지 않는다. 실제 개발 빌드가 필요하다.
- iOS와 Android 모두 플랫폼 차원에서 위젯의 버튼·체크 상호작용을 지원한다.
- Expo SDK 58 공식 Widgets 문서는 Android와 iOS를 지원한다. 업그레이드 또는 플랫폼별 구현 중 어떤 경로를 사용할지는 미정이다.
- 위젯 표시가 바뀌는 것과 앱·서버 기록까지 보존되는 것은 별도 검증 대상이다. 앱의 AsyncStorage와 위젯이 저장소를 자동으로 공유한다고 가정하지 않는다.
- 앱이 완전히 종료된 상태에서 위젯 체크 후 다시 앱을 열었을 때 기록이 남는지, 오프라인 체크와 중복 터치가 어떻게 동기화되는지 확인해야 한다.
- SDK 57의 `expo-notifications`는 기기 내 알림 예약을 지원한다. 첫 알림 구현은 기기 내 예약부터 검토하며, 친구 활동을 알리는 원격 푸시는 별도 범위다.

## 다음 설계 단계

운영 규칙은 확정했으며 아래는 아직 정하지 않은 설계 항목이다.
