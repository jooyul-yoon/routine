# 하루결

`2026 루틴달력2.0.xlsx`와 `주간 플래너2.0.xlsx`를 바탕으로 만든 개인 루틴 앱입니다. React Native와 Expo SDK 57을 사용하며 iOS와 Android에서 같은 기록 모델을 사용합니다.

## 실행

Node.js 24 LTS를 권장합니다. 현재 컴퓨터의 Node 23은 React Native 0.86 지원 범위 밖이므로 설치 시 엔진 경고가 발생합니다.

```sh
git clone https://github.com/jooyul-yoon/routine.git
cd routine
npm install
cp .env.example .env.local
npm start
```

같은 Wi-Fi에 연결된 휴대폰에서 SDK 57을 지원하는 Expo Go로 터미널 QR을 스캔합니다. 아이폰은 카메라, 안드로이드는 Expo Go의 QR 스캐너를 사용합니다. SDK 호환 여부는 Expo Go에 표시되는 안내를 따릅니다.

```sh
npm run ios      # Xcode iOS Simulator 필요
npm run android  # Android SDK와 에뮬레이터 필요
npm run web      # 네이티브 공통 코드의 브라우저 미리보기
```

## 첫 버전의 기능

- 오늘: 8개 기본 루틴 체크, 날짜 이동, 할 일 추가·완료·삭제, 기분 5단계, 수면 시간, 한 줄 기록
- 주간: 월요일 시작 주간 목표·보상·한 문장, 요일별 달성률, 루틴 체크 현황, 날짜별 할 일
- 월간: 실제 연도·월의 달력, 날짜별 기록 진입, 루틴별 달성률, 기록한 날의 평균 수면
- 내 루틴: 추가·이름 및 분류 수정·보관, JSON 백업 공유와 복원
- 이메일 회원가입·로그인, 계정별 Supabase 서버 저장과 오프라인 대기 기록 동기화
- AsyncStorage 기기 저장, 직렬 저장으로 빠른 연속 입력 순서 보장, 저장 실패 재시도

기본 루틴은 7:30 기상, 말씀 묵상, 15분 기도, 목원 한 명 연락, 운동, 프로틴 쉐이크, 물 2L, 비타민입니다. 모든 루틴은 매일 반복합니다.

## 계산과 기록 원칙

등록일부터 보관 전날까지의 루틴만 해당 날짜의 분모에 포함합니다. 과거 날짜에 새 루틴을 소급 적용하지 않습니다. 보관해도 체크 데이터는 삭제하지 않으며 보관일부터 달성률에서 제외합니다. 이름 수정은 과거 화면에도 반영됩니다.

주간·월간 달성률은 오늘까지의 완료 횟수를 오늘까지 유효한 전체 루틴 횟수로 나눈 값입니다. 미래 날짜는 분모에서 제외합니다. 할 일은 루틴 달성률과 별개로 완료 수를 표시합니다. 수면 0시간과 미기록은 구분합니다. 날짜는 기기의 현지 날짜를 사용하며 실행 중 날짜가 바뀌거나 앱으로 돌아오면 갱신합니다.

엑셀의 루틴 항목과 플래너 구조를 반영했습니다. 과거 체크·할 일·메모 데이터 가져오기, 엑셀 자동 동기화, 알림, 요일별 반복 설정은 포함하지 않습니다.

## Supabase 연결

`.env.local`에 프로젝트 URL과 공개 publishable 또는 anon 키를 설정합니다. 앱에는 관리자 키나 DB 비밀번호를 넣지 않습니다. `.env.local`은 Git에서 제외됩니다. 이미 연결 설정이 있는 작업 폴더에서는 예제 파일로 덮어쓰지 마세요.

```sh
supabase link --project-ref YOUR_PROJECT_REF
supabase db push
```

`supabase/config.toml`은 로컬 개발용 설정이며 운영 프로젝트 설정을 자동 변경하지 않습니다. 이메일 로그인이 켜져 있어야 하며 이메일 인증을 사용하면 회원가입 메일로 인증한 후 앱에 돌아와 로그인합니다. 실제 메일 수신과 휴대폰 실행은 별도로 검증해야 합니다. 운영용 메일 발송을 위해서는 Supabase의 SMTP·인증 URL 설정을 준비해야 합니다. 비밀번호 재설정·계정 삭제 화면과 소셜 로그인은 아직 포함하지 않습니다.

### 저장 구조와 충돌 처리

`routine_journals`는 사용자별로 기존 Journal 형식의 JSONB, 서버 revision, 갱신 시각을 보관합니다. 한 문서에 루틴·일별 체크·할 일·컨디션·주간 계획을 함께 저장해 백업 형식과 원자적 저장을 유지합니다. 현재 계정당 문서 크기는 최대 5MiB입니다.

- RLS는 본인 데이터 조회만 허용합니다. 익명 읽기·쓰기와 클라이언트의 테이블 직접 쓰기를 차단합니다.
- 저장은 `put_routine_journal` 함수를 사용합니다. 로그인 계정과 요청 계정이 일치해야 하며, 서버 revision이 맞을 때만 저장합니다. 다른 계정으로 전환 중이던 요청도 차단합니다.
- 기기 캐시와 동기화 기준 데이터를 계정 ID별로 분리합니다. 로그인 전 기록은 별도 공간에 보관하고 사용자가 선택할 때만 계정으로 가져옵니다.
- 입력 후 기기에 먼저 저장하고 약 1초 뒤 서버 동기화를 시도합니다. 실행 중에는 30초마다 확인하고 앱으로 돌아올 때도 동기화합니다. 푸시 방식의 실시간 구독은 아닙니다.
- 공통 동기화 기준과 양쪽 변경을 비교합니다. 서로 다른 체크·할 일·메모 수정은 병합하고 같은 항목의 수정이나 삭제 충돌은 사용자가 우선할 기록을 선택합니다. 공통 기준이 없는 첫 연결의 충돌은 선택한 전체 기록을 사용합니다.
- 업로드 도중 새로 입력한 내용도 남겨 다음 동기화에 반영합니다. 기기 저장에 실패하면 서버에 올리지 않고 저장 재시도를 기다립니다.

## 백업

내 루틴 → 기록 백업하기에서 JSON 내용을 복사하거나 시스템 공유 기능으로 본인이 선택한 곳에 보관합니다. 복원은 형식을 검증하고 두 번째 확인 버튼을 누른 후 현재 기록을 교체합니다. 로그인 중이면 복원한 내용도 서버로 동기화합니다. 복원 전 현재 기록을 먼저 백업하세요. 앱 삭제·기기 교체 전 서버 동기화 완료 여부와 백업을 확인하세요.

## 검증

```sh
npm run typecheck
npm test
npm run lint
npx expo export --platform all
```

15개 도메인·동기화 테스트는 날짜 경계·윤년·루틴 추가와 보관 시 과거 달성률 보존·백업 검증·독립 변경 병합·충돌·오프라인 재실행·업로드 중 수정·저장 실패·계정 분리를 확인합니다. 번들 생성은 스토어 배포용 IPA/APK 빌드나 실제 기기 검증을 대신하지 않습니다.

연결한 서버의 접근 제한과 원자적 저장을 검증하려면 아래 명령을 사용합니다. 로그인된 Supabase CLI를 사용하며, 임시 계정 두 개와 테스트 기록을 생성한 후 정리합니다. 관리자 키는 메모리에서만 사용하고 출력하거나 파일에 저장하지 않습니다.

```sh
node scripts/verify-supabase.mjs YOUR_PROJECT_REF
```

## 설치 파일 빌드

`eas.json`에 내부 테스트와 운영 빌드 설정이 있습니다. Expo 계정 및 프로젝트 연결 후 실행합니다. 아이폰 배포는 Apple 서명·기기 등록 또는 TestFlight 설정이 추가로 필요합니다.

```sh
npx eas-cli@latest build:configure
npx eas-cli@latest build --profile preview --platform android
npx eas-cli@latest build --profile preview --platform ios
```

실제 앱스토어 등록과 서명된 설치 파일 생성은 수행하지 않았습니다.
